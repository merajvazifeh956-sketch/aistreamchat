## مولتی‌لوکیشن (همهٔ لوکیشن‌ها داخل یک پنل)

### اول یک نکتهٔ مهم دربارهٔ Reality

پروتکل **VLESS + Reality** از CDN (مثل Cloudflare) رد نمی‌شود، چون CDN خودش TLS را terminate می‌کند و دست‌دادن Reality همان لحظه می‌شکند. پس ترفند «اسکن و پیدا کردن IP ثابت» (همان Cloudflare Preferred IP / 优选IP که برای VMess+WS استفاده می‌شود) **برای Reality وجود ندارد**.

برای Reality، «لوکیشن» یعنی **سرور واقعی در همان کشور**: هر لوکیشن باید یک سرور/نود جدا با IP خودش داشته باشد. IP هر نود همان IP پایدارِ همان لوکیشن است — چیزی برای «پیدا کردن» نیست، باید سرورِ آن کشور را داشته باشید.

### راه درست: قابلیت Multi-Node خود 3x-ui

نسخهٔ 3.4.2 این ریپو قابلیت **Multi-Node** دارد: یک پنلِ **مستر** چند **نود** (هر نود = یک لوکیشن) را از داخل همان پنل مدیریت می‌کند، اینباندها را روی نودها سینک می‌کند و سابسکریپشنِ همهٔ لوکیشن‌ها را یکجا می‌دهد. یعنی دقیقاً همان چیزی که می‌خواهید: لوکیشن‌ها داخل یک پنل، بدون باز کردن پنل جدا برای هر لوکیشن و بدون دست‌زدن به TCP proxy.

ریلوی فقط ۴ ریجن دارد؛ نزدیک‌ترین ریجن به سوئد/آلمان «اروپای غربی (آمستردام)» است. برای هر لوکیشن یک سرویس جدا (نود) می‌سازید:

| لوکیشن | ریجن در داشبورد ریلوی |
|---|---|
| سوئد | EU West (Amsterdam) |
| آلمان | EU West (Amsterdam) |
| آمریکا | US West (California) یا US East (Virginia) |
| سنگاپور | Southeast Asia (Singapore) |

**مراحل (فقط با داشبورد، بدون ترمینال):**
1. **یک سرویس = پنل مستر.** پروژه بسازید و این ریپو را به‌عنوان سرویس اضافه کنید (New Service → همین ریپو). این پنل مرکزی شماست.
2. **برای هر لوکیشن یک سرویس = نود.** سرویس مستر را **Service → ⋯ → Duplicate** کنید و نام بگذارید مثلاً `node-sweden`، `node-germany`، `node-usa`، `node-singapore`.
3. **ریجن هر نود** را از **Service → Settings → Deploy → Region** بچینید (طبق جدول بالا).
4. **نودها را به مستر اضافه کنید.** در پنل مستر، از قابلیت Multi-Node (منوی Nodes) هر نود را با **آدرس پنل خودش** (خط `panel:` در لاگ همان سرویس) و `admin / admin` اضافه کنید. پنلِ هر نود فقط درگاه API است؛ از این به بعد فقط با پنل مستر کار می‌کنید.
5. **اینباند Reality را یک‌بار روی مستر بسازید** و روی همهٔ نودها deploy/سینک کنید. UUID و کلید Reality بین همهٔ نودها یکی می‌ماند، پس یک کلاینت روی هر لوکیشنی وصل می‌شود.
6. **لینک/سابسکریپشن**: از پنل مستر، سابسکریپشن همهٔ لوکیشن‌ها یکجا ساخته می‌شود؛ کاربر داخل کلاینتش لوکیشن دلخواه را انتخاب می‌کند.

**آدرس کلاینت هر لوکیشن** = خط `proxy:` در لاگِ نود همان لوکیشن (دامنهٔ TCP proxy + پورت رندوم). یعنی لوکیشن سوئد آدرس نود سوئد را می‌گیرد، نه آدرس سرور اصلی — دقیقاً همان رفتاری که خواستید، بدون تغییر دستی TCP proxy.

> اگر هر لوکیشن دامنه‌اش فیلتر شد، بقیه مستقل‌اند و کار می‌کنند.
>
> **IP پایدار واقعی:** IP ریلوی مشترک (shared) است و ممکن است عوض یا فیلتر شود. اگر لوکیشن با IP اختصاصیِ واقعاً پایدار و پورت 443 تمیز (بدون پورت رندوم TCP proxy) می‌خواهید، برای هر لوکیشن یک VPS ارزان (Hetzner/OVH/Contabo و…) بگیرید و همان را به‌عنوان نود اضافه کنید؛ مستر می‌تواند خودش روی ریلوی بماند.

(یک اسکریپت اختیاری `deploy-multi.sh` هم هست برای کسانی که CLI ریلوی نصب دارند؛ لازم نیست.)

## اتصال با IPهای کلادفلر (Cloudflare) — جایگزین Reality

برای اینکه کلاینت‌ها به **IPهای کلادفلر** وصل شوند (و IP واقعی سرور ریلوی لو نرود)، پروتکل باید **VLESS + WebSocket** باشد. Reality را نمی‌شود از کلادفلر رد کرد: کلادفلر TLS را خودش terminate می‌کند و دست‌دادن Reality همان‌جا می‌شکند.

در این نسخه پورت `443` به‌صورت **HTTP** اکسپوز شده (نه TCP)، پس کلادفلر می‌تواند روی آن بیاید.

### مراحل (داشبورد + پنل)

1. **یک دامنه روی کلادفلر** داشته باشید (مثلاً `vpn.example.com`).
2. **دامنه را به ریلوی وصل کنید**: داشبورد ریلوی → **Settings → Networking → Domains → Add Domain** و دامنه را به **پورت 443** ببندید (پورت پنل 2053 جدا می‌ماند). ریلوی یک رکورد CNAME + TXT می‌دهد.
3. **در کلادفلر**: همان دامنه را با **Proxy روشن (ابر نارنجی)** بسازید — CNAME به مقصدی که ریلوی داده — و **SSL mode را Full** بگذارید.
4. **در پنل، اینباند VLESS بسازید**:
   - Protocol: VLESS
   - Port: `443`
   - Transport: **WebSocket (ws)** — مسیر مثلاً `/ws`
   - Security: **none** — TLS را خاموش بگذارید، چون TLS را کلادفلر/ریلوی انجام می‌دهند (ریلوی درخواست را به‌صورت HTTP ساده به اینباند می‌رساند)
5. **لینک را بردارید و آدرس را با IP کلادفلر عوض کنید**:
   - آدرس: یک IP سریع کلادفلر (اسکن کنید، پایین را ببینید)
   - پورت: یکی از پورت‌های HTTPS کلادفلر: `443, 2053, 2083, 2087, 2096, 8443`
   - SNI / Host: همان دامنهٔ شما (`vpn.example.com`)
   - مسیر WS: همان `/ws`
   - TLS: روشن (اتصال به کلادفلر، نه مستقیم به ریلوی)

### پیدا کردن IP سریع کلادفلر (优选IP / Preferred IP)

روی سیستم خودتان (نه سرور) ابزار **CloudflareSpeedTest** را اجرا کنید:

```bash
# لینوکس / مک
curl -sL https://github.com/XIU2/CloudflareSpeedTest/releases/latest/download/CloudflareST_linux_amd64.tar.gz | tar xz
./CloudflareST -n 200 -t 5 -dn 10 -sl 5

# ویندوز: از همان ریپو فایل zip را بگیرید و CloudflareST.exe را اجرا کنید
```

خروجی چند IP برتر با تأخیر کم می‌دهد؛ همان IP را در کلاینت به‌عنوان آدرس بگذارید (SNI = دامنهٔ خودتان). IPهای کلادفلر anycast هستند و معمولاً فیلتر نمی‌شوند؛ اگر یکی کند یا فیلتر شد، IP بعدی را امتحان کنید.

> **نکته دربارهٔ لوکیشن:** با کلادفلر، ورودیِ اتصال لبهٔ کلادفلر است (نه IP سرور ریلوی)، پس «لوکیشن ورودی» دیگر با IP انتخاب نمی‌شود؛ خروجی همان ریجن سرور ریلوی است. اگر لوکیشن ورودی جدا لازم دارید، همان روش مولتی‌نود بالا را با اتصال مستقیم Reality استفاده کنید.
>
> **Reality را می‌خواهید؟** Reality فقط اتصال مستقیم (بدون کلادفلر) کار می‌کند. اگر هر دو را می‌خواهید، یک پورت دیگر را `tcp` اکسپوز کنید و یک اینباند Reality جدا بسازید؛ ولی از کلادفلر رد نمی‌شود.

## حالت مخفیانه (کد مبهم‌شده)

- `start.sh` مبهم‌سازی شده (محتوای واقعی base64 است)؛ فایل خوانای اصلی `start.plain.sh` است که **در `.gitignore` قرار دارد** و نباید پوش داده شود. اگر خواستید تغییری بدهید: `start.plain.sh` را ویرایش کنید و دوباره `base64 -w0 start.plain.sh` را در `start.sh` بگذارید.
- `Dockerfile` هم بدون کلمات آشکار بازنویسی شده (آدرس دانلود به‌صورت base64).
- در زمان اجرا: مسیر پنل رندوم است (مثل `/a7K3q2Z9`)، روت 404 می‌دهد، و نام پروسه در `ps` خنثی است (`webapp`).

## متغیرهای محیطی (همه اختیاری)

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `WEB_PORT` | 2053 | پورت وب‌پنل |
| `WEB_PATH` | رندوم | مسیر پنل؛ خالی = روت `/` |
| `LOCATION` | ریجن ریلوی | برچسب این اینستنس در لاگ |
| `APP_NAME` | `webapp` | نام پروسه در `ps` |

اطلاعات هر اینستنس (لوکیشن، پورت، مسیر، آدرس پنل) در لاگ و در `/etc/x-ui/panel-info.txt` ذخیره می‌شود.
